# Project Rules

## Technology

- Build the Production Portfolio with **Vanilla HTML, CSS, and JavaScript**.
- Do not introduce a frontend framework, UI library, build framework, or dependency unless the project requirements explicitly change.
- Prefer semantic HTML, standard browser APIs, and small, focused files.
- Keep JavaScript behavior in external script files and register interactions with event listeners; do not use inline event-handler attributes such as `onclick`.

## Milestone workflow

- Work on one milestone at a time, in the order M1 -> M2 -> M3 -> M4.
- Before starting a milestone, review its tasks, completion criteria, and checks in `TASK_DECOMPOSITION.md`.
- Keep each change scoped to the active milestone. Avoid folding unrelated cleanup or later-milestone work into it.
- Complete the listed checks and review the resulting changes before considering the milestone done.
- Record findings, verification results, and any justified deviations in the milestone review notes.
- Do not begin the next milestone until the active milestone meets its completion criteria.
- Use the commit message specified for a milestone when committing that milestone; keep its changes separate from other milestones.
